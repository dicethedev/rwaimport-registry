# Security and data-integrity reports

Use GitHub's private vulnerability reporting for smart-contract verification logic,
dependency vulnerabilities, or issues that could expose maintainers and users to harm.
Please do not disclose an exploitable issue publicly before maintainers can assess it.

Ordinary data problems are not security vulnerabilities. Open a regular GitHub issue for:

- an incorrect issuer, asset name, classification, or compliance statement;
- a wrong, compromised, or outdated contract address;
- an inaccessible or outdated evidence link;
- a duplicate asset or deployment;
- a token-standard classification error.

Include the affected asset ID, chain, contract address, expected correction, and at least one
primary or authoritative source. Never include private keys, personal identity documents,
API keys, or other sensitive information in an issue.
